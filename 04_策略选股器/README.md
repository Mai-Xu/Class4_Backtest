# 04 策略选股器 · 因子组合 WebUI

把 `03_因子挖掘` 挖出来的 **390 个因子**做成一个能点着玩的组合策略选股器：
左边选因子、拉权重，点一次「开始回测」，右边给出 10 亿元资金在
**2025-01-02 → 2026-09-30** 的样本外成绩，并与三条对照曲线画在同一张图里。

```
python 04_策略选股器/build_ui_data.py     # ① 预计算（约 1 分钟，只需跑一次）
python 04_策略选股器/app.py               # ② 起服务并自动开浏览器（默认 127.0.0.1:8770）
```

> 前置：`feathers/` 原始行情不在仓库里（约 226 MB），放置方式见 [`../feathers/README.md`](../feathers/README.md)；
> 也可以用 `CLASS4_DATA_DIR` 或 `--data-dir` 指向任意位置。
>
> 依赖：`pandas / numpy / pyarrow / flask`。服务端**不加载**原始行情，只读
> `out/cache/selector/` 里的紧凑产物（约 25 MB），启动 1 秒内、单次回测 < 1 秒。

## 1. 两种玩法

| 模式 | 你给什么 | 程序怎么算 | 本质 |
| --- | --- | --- | --- |
| **A 打分合成**<br>（默认） | 每个因子的**打分权重** wᵢ | 每个因子先做当日横截面**秩 z**（池内排序、抗极值），方向按样本内 IC 符号 sᵢ，合成总分 `S = Σ (wᵢ/Σw)·sᵢ·zᵢ` → 买分数前 N 只等权 | 一个组合、一份资金 |
| **B 资金分配** | 每个因子的**资金占比** wᵢ | 每个因子各自跑一个「前 N 只等权」子策略，资金按权重分给各子策略，组合净值 `= Σ wᵢ × 净值ᵢ`（分账户执行，权重随净值自然漂移） | N 个子账户、收益相加 |

两种模式共用同一套选股与撮合口径；切换模式只改「怎么把因子拼起来」。

**默认配置**：`ICIR 精选 8 个`——样本内 \|IC\|≥0.02、\|ICIR\|≥0.5 的非冗余簇代表因子，
每个家族最多取 2 个，按 \|ICIR\| 降序取 8 个，初始权重 = \|ICIR\|；持仓 1700 只（≈ 打分前 35%，项目主推的宽持仓用法）。

## 2. 统一口径（与工作 ②③ 完全一致）

| 项目 | 取值 |
| --- | --- |
| 初始资金 | **10 亿元** |
| 交易费用 | 佣金 **万一**（单边）+ 印花税 **万五**（卖出） |
| 回测区间 | **2025-01-02**（开盘建仓）→ **2026-09-30**（开盘清仓），424 个交易日、21 次月度调仓 |
| 股票池 | 非 ST 全市场动态池：上市满 250 交易日、20 日均成交额 ≥ 2000 万、股价 ≥ 2 元、剔除一字板 / 停牌 / 无涨跌幅限制标的（每期 4709 ~ 5042 只） |
| 调仓节奏 | 每月最后一个交易日**收盘**出信号 → **次日开盘**按复权价成交 |
| 目标仓位 | 单票等权、总仓位 **98%**（留 2% 现金缓冲，与引擎 `gross_limit` 一致） |
| 调仓死区 | `band = max(min(2e5, 0.2·cash/N), min(0.25/N, 2e-3)·NAV)`（用户可调缓冲带 1.0× ~ 2.0×） |
| 记账 | **复权份额**：`units = 原始股数 / cumadj`，`市值 = units × 复权价`，分红自动留在净值里 |
| 定方向 | 只用 **2021-01 ~ 2024-12** 的样本内 IC 符号；2025 年之后的数据不参与任何选择 |

## 4. 因子卡片里有什么

选中/展开任意因子即可看到（全部为**样本内 2021-01 ~ 2024-12** 口径）：

- **一句话说明**（`desc`，来自因子字典）；
- **IC20 / ICIR**：20 日前视收益的秩 IC 均值与信息比率；
- **多空年化**：十分层多空组合的净年化（因子原值口径、与 IC 同号）；
- **策略年化 / 夏普 / 最大回撤**：按「打分前 1700 只等权、月频、含万一+万五」实测的曲线与指标；
- **覆盖率、冗余簇**：同一簇的因子信息高度重叠，程序会在展开时提示「与已选因子同簇」；
- **样本外 IC（2025-2026）**：灰字事后参考。**用它挑因子会引入样本外选择偏差**，别当决策依据。

## 5. 快速口径 vs 逐笔撮合引擎

WebUI 用向量化口径（`fastsim.py`）复刻引擎的记账规则，但**不模拟** T+1、涨跌停/停牌挡单、
参与率上限与执行窗口内逐日补单——这些摩擦是引擎独有的成本。对拍证据（`verify_vs_engine.py`，
同一分数面板、同参数）：

| 组合 | 快速年化 | 引擎年化 | 差值 | 年换手（快速 / 引擎） | 日收益相关 | 净值最大相对偏差 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| MF1700_raw | 22.70% | 22.51% | **+0.19pp** | 10.02 / 10.00 | 0.99998 | 0.37% |
| N=2500 | 21.03% | 20.82% | +0.22pp | 4.15 / 4.15 | 0.99997 | 0.34% |
| N=1200 | 21.05% | 20.86% | +0.19pp | 8.69 / 8.68 | 0.99997 | 0.36% |
| N=800 | 20.00% | 19.86% | +0.13pp | 10.51 / 10.48 | 0.99996 | 0.31% |
| N=400 | 17.81% | 17.54% | +0.27pp | 13.23 / 13.06 | 0.99983 | 0.53% |
| N=200 | 15.01% | 14.70% | +0.31pp | 15.32 / 14.55 | 0.99866 | 1.23% |
| 规模中性化 | 20.60% | 20.35% | +0.25pp | 9.97 / 9.95 | 0.99998 | 0.42% |

结论：**日收益相关 ≥ 0.9987，年化系统性偏高 0.13 ~ 0.31pp**（就是被挡单摩擦省下来的那一部分），
持仓越集中偏差越大。要逐笔落库、看被挡委托明细，直接跑 `03_因子挖掘/s23_multifactor_bt.py`。

## 7. HTTP 接口

```bash
GET  /api/bootstrap
     → {meta, factors:[390 条含样本内历史表现], benchmarks:[3 条], default}
POST /api/run
     {"mode":"score"|"allocate", "factors":[{"name":"mr_rev20","weight":3.0}, ...],
      "n_hold":1700, "buffer":1.0}
     → {curves, stats, annual, monthly, drawdown, factors, holdings, plan, final_asset, ...}
```

幂等请求带 LRU 缓存（48 条），同一组参数再点一次是毫秒级返回。因子数上限 20 个，持仓数 30~3000。

## 8. 已知限制

- 样本外只有 21 个月，年化差异的标准误约 ±4pp；同日同池的随机对照年化区间就有 [19.5%, 22.7%]，
  别把 1~2pp 的差距当规律。
- 快速口径不含涨跌停/停牌/参与率约束，年化系统性偏高 0.13~0.31pp（见第 5 节）。
- 面板是**月频**信号：所有因子都在每月最后一个交易日取值，不给日频择时。
- 因子方向用样本内 IC 符号固定，不做滚动更新；也没有行业中性化（数据里没有行业分类）。
- **当期横截面无差异就不调仓**：日历类因子（如「年末×反转」在非 12 月恒为 0）有 89 个「因子×期」是全池同值的，
  这些期程序不调仓、也不按代码顺序乱选（否则会选出 000001 开头的一串股票）；换手与结果都会如实反映这一点。
- 因子卡片上的「样本内表现」本身就是样本内挑出来的，只能用来**排除明显不合理的因子**，
  不能当作未来收益预期。
