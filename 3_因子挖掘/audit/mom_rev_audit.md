## 0. 方法，以及"这个对比有能力发现问题"的证明

1. **输入口径先自查（不是假设）**：脚本自己用 feathers 重搭面板 `adj = 原始价 × cumadj_clean`（不调用 `md.adj_close`），
   与 `md.adj_close` 逐格相同（`max|diff| = 0`，NaN 掩码 0 处不一致）；自建日收益 `adj[t]/adj[t-1]-1` 与 `md.ret`
   掩码完全一致、数值 `max|diff| = 0`（输出 [1]）。注意 pandas 的 `pct_change()` 默认 `fill_method='pad'` 会先把 NaN 前向填充，
   朴素实现里显式绕开了它，否则会造出假差异。
2. **路径 A：朴素重算**，完全不 import `mom_rev` 的内部函数：复权面板自己乘；区间收益用「连乘 (1+r)」；
   统计量用 pandas `mean / var(ddof=1) / notna`；窗口端点与覆盖阈值按各 docstring 声称的口径复刻；
   在 6 主日期 + 2 边界日 × 5451 列上逐格比较，NaN 掩码要求**完全一致**（记录"仅模块有值/仅朴素有值"两个方向的错位数）。
3. **路径 B：端点恒等式**：另用「日收益连乘 + 显式写死端点」再算一遍，并给出**错一位端点的对照值**。
   对照值远大于 0（例如 rev5 的 `[t-5,t-1]` 差 **0.698**、rev20 差 **0.698**、ltrev3y 的 `[t-756,t-1]` 差 **0.858**、
   ovn 的 `[t-20,t-1]` 差 **0.721**、mom_acc 的"不 skip 版"差 **4.33**、mom_ir12 的"12-0 版"差 **2.79**），
   而正确端点全部 ≤ 4.3e-14 → 说明本对比确实能发现一天/一个月的端点错误，而不是"随便都过"。
4. **路径 C：逐列 python `for` 循环**（最朴素写法）交叉验证 `mr_ltrev3y` / `mr_mom_ir12`，结论一致（输出 [4b]）。
5. **因果性三重检验**：
   (a) 项目自带的 `Ctx.truncated(t)` 截断检验（8 个日期，12 因子）→ **截断差恒为 0.00e+00**；
   (b) **未来行投毒**：把 `t` 之后所有可见面板（close/open/high/low/adj_close/cumadj_clean/amt/num_trades/ret/ret_ok/listed）
   换成垃圾值后重算 → 12 个因子要么 0，要么与"同数据纯副本"基线同量级（见第 2.1 节）；
   (c) **阳性对照** `leak_control`（故意偷看 t+1 行）在同一投毒下差 **4.04e+04**，证明投毒确实有牙齿。
6. **项目自带检查**：`python -m factor_zoo.selfcheck mom_rev` → 12/12 通过，24 个调仓日截断差 `0.00e+00`。
7. **反事实探针**：把复权因子全设为 1（改用未复权价）重算，看因子值是否变化（验证复权口径，见第 2.5 节）。

## 2. 逐条回答"易错点"清单

### 2.1 窗口端点：`[t-w+1, t]` 还是 `[t-w, t]`？是否误用 `t+1`、负索引、破坏截断的写法？

**全部是 `[t-w+1, t]`（含 t，共 w 行收益日）；未发现 `t+1`、`C.n`、负索引或破坏截断的写法。**

证据：

- 正确端点的恒等式全部 ≤ 4.3e-14；把同一套恒等式**整体挪一天**（`[t-w, t-1]`，即"少算今天、多算一天前"）立刻炸开：
  rev5 **0.698**、rev20 **0.698**、ltrev3y **0.858**、ovn **0.721**、intra **0.653**；高点因子 `[t-250, t-1]` 差 **0.20 / 0.34**（输出 [4]）。
- 端点逐条实测（收益日）：rev5 `[t-4,t]`、rev20 `[t-19,t]`、mom3_1 `[t-62,t-21]`、mom6_1 `[t-125,t-21]`、
  mom12_1 `[t-251,t-21]`、ltrev3y `[t-755,t]`（不足则退化）、nearhigh/hh_dist `[t-249,t]`、ovn/intra `[t-19,t]`、
  mom_acc `[t-83,t-21] − [t-251,t-84]`、mom_ir12 `[t-251,t-21]`。
- 源码 grep（脚本化，见下）：`t\s*\+\s*1` **0 处**、`C\.n` **0 处**、代码中**无负索引**（唯一 `[-w+1, 0]` 出现在
  `_daily_part` 的 docstring 文字里）；`_daily_part` 取 `C.C[i-1]` 前先 `i = i[i >= 1]` 过滤，不可能回绕；
  所有窗口经 `C.sl`（`lo = max(t-w+1, 0)`）或显式 `i0 < 0 → 全 NaN`，截断后不变 → 截断检验差恒为 0。
- `_px_ret` 的窗口是"价格端点" `[i0, i1] = [t-skip-window, t-skip]`，换算成收益日即 `[i0+1, i1]`，与上表一致（无差一错误）。

### 2.2 skip 类因子（剔除最近 1 个月）：端点是否正确？两段是否意外重叠？

**端点正确（右端点是 t-21，正好剔除 t-20..t 共 21 个交易日）；两段不重叠、不留缝。**

证据 a（直接投毒）：把 `t-21` 之后（含 t）的行全部换成垃圾值后重算，5 个 skip 因子的值**逐格不变**：
`mr_mom3_1` **0**、`mr_mom6_1` **0**、`mr_mom12_1` **0**、`mr_mom_acc` **0**、`mr_mom_ir12` **8.88e-15**
（后者等于"同数据纯副本"基线 8.88e-15，纯浮点归约噪声）。同一投毒下非 skip 因子（rev5/rev20/ltrev3y/nearhigh/
hh_dist/ovn/intra）立刻变化且 NaN 掩码都变 → 证明 skip 类确实没读最近 1 个月的数据（输出 [5b]）。

证据 b（两段拼接）：`(1+fast)(1+slow)-1` 与 `mr_mom12_1`（实现上就是 `[t-251,t-21]` 全区间）逐格一致
（max|diff| 6.7e-15 ~ 2.9e-14，掩码不一致 0 处，输出 [6d]），而 fast 是 `[t-83,t-21]`、slow 是 `[t-251,t-84]`，
两者相加正是 231 个收益日 → 在 231 天里**没有重叠也没有缺口**。

### 2.3 除法 / 取对数是否可能产生 ±inf？

**否。8 个审计日 ±inf = 0；全样本 1643 日 × 12 因子扫描 ±inf = 0（输出 [3]、[7]）。**

证据：
- 价格守卫：`_px_ret` 要求 `isfinite(num) & isfinite(den) & den > 0`；面板内原始收盘最小 **0.09**、复权收盘最小 **0.1228**，
  恒 > 0，`den<=0` 分支在本数据上不可能触发；高点因子的分母是收盘价、`hmax ≥ close`。
- 对数守卫：`_cum_ret` 走 `expm1(Σ log1p(r))`。面板内**日收益最小值 −0.9644（恒 > −1）**，`log1p` 不会出 −inf；
  即使某格恰为 −1，`expm1(-inf) = −1` 仍是有限值；若出现 < −1（本数据没有）则得 NaN，也不是 inf。
- 末行边界：2026-10-16 有 2 只（`601059.SH`、`601198.SH`）close 有效但 cumadj 为 NaN → 复权价 NaN →
  12 个因子在这 2 格返回 NaN（不会退化成用未复权价硬算）。

### 2.4 停牌日与上市前 NaN 的处理

**符合声称口径（停牌日贡献 0 收益、上市前 NaN 自然传播），但有两点必须记录（不是 bug）。**

- 停牌面板事实：23229 个停牌格（`listed & amt<=0`），其中 `O==H==L==C` 占 **23229/23229**；
  日收益 R 有 **23182 格恰好为 0**、**22 格为 NaN**（停牌发生在上市首日）、其余 25 格 `|R| ≤ 2e-6`
  （除权日的 0.01 元最小报价单位残差）。→ 价格比口径下停牌段天然是 0 收益，隔夜/日内日度项在停牌日也恒为 0（O=C=前收）。
- 上市前/退市后价格 NaN，比值与掩码统计自然传播；8 个日期 12 因子的 NaN 掩码与朴素实现**逐格一致（0 处不一致）**，
  含 2020-01-02（t=0，窗口全空 → 全 NaN）与 2026-10-16（含上面 2 格）。
- 记录项 (a)：停牌日收益为 0 但**finite**，会计入 `_cum_ret` 的"有效日数"配额。实测有少数格子因此拿到值：
  例如 2024-06-28 `mr_ltrev3y` 有 **36 格**、2020-03-31 `mr_ovn_mom20`/`mr_intra_mom20` 各有 **22 格**，
  其窗口内"真实成交日数"少于该因子阈值（输出 [6e]）。
- 记录项 (b)：窗口不含 t 的因子会给"t 日已无价格（退市/长停）的股票"返回值：6 主日期合计
  `mr_ltrev3y` **371 格**、`mr_mom_ir12` **85 格**、mom3_1/6_1/12_1/mom_acc 各 **35 格**、ovn/intra 各 **11 格**
  （输出 [6] 最后一列）；单看 2025-06-30，`mr_ltrev3y` 有 107 格、`mr_mom12_1` 有 3 格。
  这不是未来函数（只用了 t-21 及更早的数据），但**下游必须先按 `md.universe()`（以 `traded` 为起点）过滤选股域**，
  否则可能给退市股建仓。`core/strategies.py`、`s08_factor_mining.py` 都走 `md.universe()`，所以主线无碍。

### 2.5 复权口径是否用对（价格/收益类必须复权）

**用对了（唯一例外是由定义决定的，不是 bug）。**

- 自建 `adj = 原始价 × cumadj_clean` 与 `md.adj_close` 逐格相同（max|diff| = 0）；`md.ret` 与自然比值逐格相同。
- **反事实**：把复权因子全设为 1（改用未复权价）后用同一套朴素公式重算，与模块值明显不同
  （取值不同的格数：`mr_rev5` 982、`mr_ovn_mom20` 5175、`mr_nearhigh250` 12639、`mr_mom12_1` 13082、
  `mr_ltrev3y` 18913，max|diff| 最高 14.1）→ 证明模块确实用的是复权价而不是原始价。
- 例外的 `mr_intra_mom20`（同日 `C/ADJ_O`）在未复权重算下差 3.1e-15、0 格变化：同一天的 open/close 被同一个
  `cumadj` 因子相乘而相消，属定义使然（除权当天日内收益率本来就不受除权影响）。
- 涨跌停/一字板识别需要的未复权价：本模块确实一处都没用（grep：无 `RAW`/`O`/`H`/`L` 直接引用），
  符合模块头部自述"纯价格族、不需要未复权价"。

## 3. 真实问题

**结论：没有发现任何数值错误，也没有发现未来函数**（12 个因子在 8 个日期上逐格一致，差异 ≤4.3e-14 = 浮点末位；NaN 掩码逐格一致；
全样本无 ±inf、截断与投毒检验全部通过）。下面是发现的**真实但非数值性**的问题，按严重程度排列：

### P1（文档错误，3 个因子）`_mom` 的内嵌 docstring 公式写错了一个月

`factor_zoo/mom_rev.py:135` 写的是 `C[t-21] / C[t-21-x*21] - 1`，而代码（`:136` → `_px_ret`）实际算的是
`C[t-21] / C[t-x*21] - 1`。用 x=3 举例，docstring 声称 `[t-83, t-21]`（4-1，63 个收益日），
代码给的是 `[t-62, t-21]`（3-1，42 个收益日）。**实现的才是标准 x-1 口径**，`FACTORS` 里的 desc
（"过去 3 个月复权收益、剔除最近 1 个月"）与实现一致，只有内嵌公式是错的 —— 但这会让后来者按 docstring 复现时对不上。

最小复现（t=1000）：

```powershell
$env:PYTHONIOENCODING="utf-8"; python -c "from core.lib import MarketData; from factor_zoo.ctx import Ctx; from factor_zoo.mom_rev import FACTORS as F; md=MarketData(); C=Ctx(md); t=1000; print(F['mr_mom3_1']['func'](t,md,C)[0]); print(C.C[t-21][0]/C.C[t-63][0]-1); print(C.C[t-21][0]/C.C[t-84][0]-1)"
```

实测输出：`-0.11186113789778196` / `-0.11186113789778196`（= `C[t-21]/C[t-63]`，代码口径） / `-0.16424682395644274`（= docstring 公式）。
**建议**：把 `:135` 的公式改成 `C[t-21] / C[t-x*21] - 1`。

### P2（口径未文档化，2 个因子）250 日高点窗口会静默退化到最短 150 日（早期日期退化到几十日）

`_high_max` 的门槛是 `cnt >= max(3, 0.6 × 实际可用行数)`，而 desc 只说"250 日复权最高价"。
后果：① 样本最初 249 个交易日（t=0..248，交易日历上到 2021-01-11）整列都按"不足 250 行"的窗口算高点 —— 例如 2020-03-31 的窗口只有
**58 行**（门槛 34.8，最小有效行 35），此列 `mr_nearhigh250` 其实不是"52 周高点接近度"；
② 即便窗口已满 250 行，仍有大量上市未满 250 日的股票用较短窗口取值（2021-06-30：**224 只**，最小 **150** 个有效日；
2022-12-30：143 只；2025-06-30：34 只）。由于"最高价"在更短窗口里必然更贴近现价，这类股票与满窗口股票**不可直接比较**。

最小复现（2021-06-30, t=360）：

```powershell
$env:PYTHONIOENCODING="utf-8"; python -c "import numpy as np; from core.lib import MarketData; from factor_zoo.ctx import Ctx; from factor_zoo.mom_rev import FACTORS as F; md=MarketData(); C=Ctx(md); t=360; v=F['mr_nearhigh250']['func'](t,md,C); H=np.isfinite(C.ADJ_H[max(t-249,0):t+1]).sum(0); f=np.isfinite(v); print('有值格', int(f.sum()), '窗口有效行<250 的格数', int((H[f]<250).sum()), '最小有效行数', int(H[f].min()))"
```

实测输出：`有值格 4068 窗口有效行<250 的格数 224 最小有效行数 150`。
**建议**：要么在 `_high_max` 里改成严格 250 行（不足即 NaN），要么在 desc/docstring 写明"不足 250 日时按可用行数 60% 退化"。

### P3（同 P2，程度较轻）`mr_mom_ir12` 的 60% 门槛（138/231）

`Ctx.stats` 的 `bad = cnt < max(3, int(0.6 × 请求窗口))`，对 `mr_mom_ir12` 是 `cnt < 138`（请求窗口固定 231）。
2021-06-30 有 **224 格**在 231 日窗口里只有 140~229 个有效日（最小 140），这些格子的"12-1 IR"实际是"短窗口 IR"。
公式本身（`mean/std×√n`）没问题，只是样本长度不齐。

**建议**：与 P2 一并处理（文档写清阈值，或统一改成满窗口）。

### P4（设计注记，docstring 已说明，不算错）`mr_ltrev3y` 混合窗口

窗口不满 756 日时退化为"可用历史 ≥252 日"，因此横截面上同时存在"近 3 年收益"（2023-02-16 之后）与
"上市以来收益"（最短 252 日）。docstring 与 desc 都写明了，实测行为与声称一致（4.26e-14），仅作提醒。
