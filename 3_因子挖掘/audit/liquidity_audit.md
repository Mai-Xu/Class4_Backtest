## 2. 审计方法

1. **独立重写**：逐列 Python 循环 + `numpy.polyfit` / `numpy.corrcoef`，窗口端点显式写死 `[max(0,t-w+1), t]`，掩码语义独立实现（不复用 `Ctx.sl/mean/std` 之外的任何模块函数）。
2. **逐格对比**：2020-03-31 / 2021-06-30 / 2022-12-30 / 2023-07-31 / 2024-06-28 / 2025-06-30（均为交易日，t=57/360/727/866/1086/1328）全横截面 5451 列，比较 `max_abs_diff` 与 NaN 位置；另随机 8 个日期复核。
3. **端点扰动扫描**：在 t=1328 逐个 lag 改写第 `t-k` 行的 A/NT/R，观察哪些股票的输出发生变化，用**实测**最长生效滞后反推真实窗口（不依赖读源码）。
4. **未来扰动检验**：改写 `t+1..t+30` 的 A/NT/R/C，要求 14 个因子输出一格不变（比项目自带的截断检查多一个独立角度）。
5. **停牌污染量化**：把 `amt==0` / `num_trades==0` 当有效观测重算一遍，统计多少只股票的因子值会改变/变成 NaN/±inf。
6. **全样本扫描**：1623 个日期 × 14 因子检查 shape、dtype、inf、覆盖率。

## 4. 易错点逐条核查

### 4.1 窗口端点：`[t-w+1, t]` 还是 `[t-w, t]`？有没有 `t+1`、负索引、破坏截断的写法？

**结论：全部 14 个因子都是 `[t-w+1, t]`，末端含 t、不含 t+1，无越界/破坏截断写法。**

证据（全部来自 `[C]` 扰动扫描与静态扫描，见附录 A.2/A.3）：

- 实测窗口行数 == 源码阅读行数：20 / 60 / 61 / 120 / 121，14/14 一致。
- 对每个因子：扰动 `t-(w-1)` 行（窗口第一行）时 5079–5115 只股票的输出发生变化；扰动 `t-w` 行（窗口前一行）时变化股票数 = 0。即窗口边界精确落在 `t-w+1`。
- 61 行窗口的 2 个因子（`lq_amt_stab60`、`lq_amt_impact60`）是"60 对"（`w+1` 行 → `w` 个相邻差），与 desc 的"60 对"一致。
- 静态扫描：源码 3 处 `int(t) + 1` 全部是切片的上界（行 96/132/238），没有把 `t+1` 当窗口末端；5 处 `[1:]`/`[:-1]` 都作用于已经截断到 `≤ t` 的窗口切片，不会读到未来行；没有任何模块级负索引访问（`C.A[-1]` 之类）。
- 截断语义：在样本第 58 天 t=57（2020-03-31）与 8 个随机日期，模块输出与"窗口在 0 处截断"的独立重算 NaN 掩码 0 差异。

### 4.2 停牌日 A=0 会不会 `log(0) → -inf`、`|r|/amt → inf`？这些位置是否返回 NaN？

**结论：模块本身不会产生 -inf/inf；停牌格一律被掩码排除。**

- 全样本 22,722 次因子调用（1623 日 × 14 因子）**0 个 inf 格**，shape/dtype 全对（附录 A.5）。
- 面板：`amt==0` 共 23,229 格（占 listed 的 0.3%；1606 只股票、1638 个交易日）；其中 `R==0` 23,182 格（若忘记掩码会 `0/0 → NaN`），`|R|>0` 25 格（会 `|r|/0 → ±inf`）。
- 反事实对照（把 0 当有效观测）：`lq_amt_log20`/`lq_nt_log20` 会有 13 只股票得到 `-inf`；`lq_amt_rel20_60` 12 只 `±inf`；`lq_amihud20/60` 55/248 只变成 NaN（0/0）；`lq_amt_trend20_120` 4 只 `±inf`。模块输出全部是有限值或 NaN。
- `lq_amt_rel20_60` 是唯一"当日 A≤0 → 当日因子 NaN"的因子（2025-06-30 的 14 只停牌股全部 NaN）；其余 13 个是滚动统计，停牌当天仍可能用窗口内其它有效日得到非 NaN（2025-06-30 停牌 14 只中有 10 只有值）。**这是设计选择而非未来函数**，但组合层必须用股票池/交易掩码剔除停牌股，不能只依赖因子 NaN——`lq_amt_rel20_60` 之外直接下注会买到停牌股。
- 另注：`num_trades` 在 2026-10-16 整行缺失、另有零星缺口，涉及 `lq_trade_size*` / `lq_nt_*`；模块把 `NT<=0`（含 0 与 NaN）都当无效，处理正确。

### 4.4 "相对活跃度"分母窗口是否把 t 日自己算进去？

**结论：是，`lq_amt_rel20_60` 的分母窗口 `[t-59, t]` 含当日 t**（源码 `liquidity.py:111-123` 调 `_mean_ok(C,t,w)` → `C.sl(t,w)`）。

- 影响量化（对照：分母改为 `[t-60, t-1]`）：

| 日期 | 值不同的股票数 | 最大差 | Pearson | Spearman |
|---|---|---|---|---|
| 2020-03-31 | 3769 | 11.16 | 0.9875 | 1.0000 |
| 2021-06-30 | 4286 | 7.04 | 0.9951 | 0.9997 |
| 2022-12-30 | 4865 | 10.50 | 0.9910 | 0.9999 |
| 2023-07-31 | 4970 | 7.42 | 0.9948 | 0.9997 |
| 2024-06-28 | 5081 | 2.14 | 0.9981 | 0.9996 |
| 2025-06-30 | 5126 | 5.47 | 0.9962 | 0.9998 |

- 机制：当日成交额在分母里自带 1/60 权重，放量时比值被机械压缩（若其它日趋近 0，含 t 口径的比值上限只有 59；不含 t 口径无上限）。小盘股单日放量时差异最大。
- 排序相关性仍 ≥0.9996，所以对组合排序的影响可能有限，但这是可以避免的口径噪声；`lq_amt_trend20_120` 的短窗嵌套在长窗内（两窗都含 t）是标准"趋势"定义，desc 已写明，不构成同类问题。

### 4.5 Amihud 分子用复权还是未复权收益？除数单位？

**结论：分子用复权日收益 `R = md.ret = adj_close.pct_change()`（core/lib.py:344-355）；除数是成交额 amt（元），乘 1e8 调量纲。**

- 模块输出与"复权收益重算"逐格一致（max diff < 1e-9，`[F1]`）。
- 若改用未复权收益 `md.ret_raw` 重算，2021-06-30 / 2023-07-31 / 2025-06-30 分别有 1237/668/1550 只（20 日）和 2169/3056/2550 只（60 日）不同，max diff 0.023–0.209 —— 说明"复权/未复权"是实质口径，模块选的是与 docstring 一致的复权口径（除权跳空不应算作非流动性冲击）。
- 单位自检：amt 中位数 8.85e7 元/日；单笔均额 `amt/num_trades` 中位数 9.59e3 元/笔（A 股合理量级；若 amt 是万元，单笔均额只有 ~1 元，不合理）→ 支持"元"；`lq_amihud20/60` 中位 0.0122/0.0162，与 `|r|/amt(元)×1e8` 量纲相符。

### 4.6 成交量与成交额是否混用？

**结论：没有混用。** 模块对 `Ctx` 的属性引用只有 `C.A`（成交额，元）、`C.NT`（笔数）、`C.R`（复权收益）、`C.sl/C.mean/C.std/C.k`，全篇没有 `volume`/`VWAP_PROXY`/`O/H/L/RAW` 面板。所有"相对量/换手代理"类 desc 都写明了"成交额代理"，Amihud 的 desc 也写明分母是 amt。本数据集没有成交量，模块没有假装有。

### 4.7 docstring / `direction` 声称方向与实际方向是否一致？

**结论：没有发现方向矛盾。** 逐项核对：`direction` 在注册表里明确定义为"先验方向（-1 = 买低值），最终由 IC 决定"，不是实现方向；实现的方向与 desc 符号一致：

- `lq_amt_impact60` desc "−corr(Δlog 成交额, 收益)" ↔ 代码 `return -c` ✓（值越大 = 放量下跌越强）；
- `lq_amt_stab60` desc "一阶自相关" ↔ 代码返回 `+c` ✓；
- `lq_amt_rel20_60` / `trend` / `slope` / `cv` / `nt_trend` 的"放量/不稳定/趋势"方向与 desc 一致 ✓；
- `lq_trade_size*` "越大 = 大资金/机构参与" ↔ 对数单笔均额及其差、偏度 ✓。
- 14 个 `direction` 全部是 `±1` 先验，未见与实现符号相反者（注意 `lq_amihud*` 用 +1、其余规模/活跃度类用 −1，这只是先验，不影响实现正确性）。

## 5. 发现的真实问题

### 5.1 `lq_amt_rel20_60` 分母含当日 t（口径争议）

### 5.2 `lq_trade_size_skew60` 的 ddof=1 归一化（口径争议，非数值错误）

- 现象：desc 说"三阶矩偏度"，教科书写法是 `m3/m2^1.5`（m2、m3 用同一 1/n 归一化）；模块把 m2、m3 都除以 `cnt-1`，等价于教科书偏度 × `sqrt((n-1)/n)`（n=有效样本数）。数值验证：模块与"同归一化的朴素实现"差 ≤1.6e-13，与教科书 ±差 4.45e-02。
- 影响：相对偏差 ≤1.399e-02（样本数最小 36 时最大；n=60 时 0.84%）。因为 n 随股票变化，这不是严格的横截面常数缩放，但影响极小（相对 `scipy.stats.skew(bias=True)` 的比例为 `sqrt((n-1)/n)`；相对 pandas `skew()` 调整口径的比例为 `(n-2)/n`，n=60 时低 3.3%——本模块处在两种常见实现之间）。
- 建议：若要与教科书/`scipy.stats.skew(bias=True)` 完全一致，把 `_trade_size_skew` 里 `n_eff = np.maximum(cnt - 1.0, 1.0)` 改为 `n_eff = np.maximum(cnt, 1.0)`（`liquidity.py:211-227`）；否则在 desc 里注明是"ddof=1 归一化的三阶矩比"。两种做法对排序影响都很小。
- 最小复现：`audit_run_full.log` 的 `[A2]` 段（同一脚本一次跑出）；源码 `factor_zoo/liquidity.py:211-227`。

### 5.3 `lq_trade_size_chg` 的措辞歧义（文档争议）

- 现象：desc "log均额20 − log均额120" 有两种读法：(a) 每日 `log(amt/笔数)` 的均值之差（模块实现，和同族 `lq_trade_size20` 的口径一致）；(b) `log(mean(amt/笔数))` 之差（Jensen 修正后不同）。
- 影响：读法 (b) 下 2021 年后 4212–5117 只股票值不同，max diff 0.23–0.42，Pearson 0.989–0.993、Spearman 0.993–0.994。不是"错"，但 desc 不足以唯一确定口径。
- 建议：desc 改为"mean(log(amt/笔数)) 20 日与 120 日之差"，或函数 docstring 明确"先取每日对数、再求均值差"。
- 最小复现：`audit_run_full.log` 的 `[F4]` 段（同一脚本一次跑出）。

## 6. 未能验证的项

- **真实换手率口径**：数据无股本/流通股，无法与"成交额/流通市值"对照验证；模块已按"成交额代理"处理并在 desc 说明，这属于数据限制而非代码问题。
- **amt 单位的外部交叉验证**：只能做内部量级自检（§4.5）。若上游数据其实是"万元"或其它单位，Amihud 的 ×1e8 缩放需要整体改，但模块内部的 `|r|/amt` 计算本身正确。
- **复权因子/除权事件本身的正确性**：属于 `core/lib.py` 数据层，不在本次审计范围。
- `lq_trade_size_skew60` 的"哪个偏度定义更优"属于研究选择，本次只量化差异，不判定优劣。
